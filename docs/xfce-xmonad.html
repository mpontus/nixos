1. Overview

This desktop combines XMonad — a keyboard-driven tiling window manager — with XFCE’s panels, session plumbing, and desktop services. The visual signature is a set of four small rounded island panels floating near the top of the screen, with a 2px accent border painted on every window and panel.

Three repositories cooperate:

2. Architecture & Ownership

Each concern has exactly one owner. This division is what keeps the setup maintainable: Nix changes are rare and declarative; XMonad changes are instant and imperative.

ConcernOwnerChange cycle
Window management, keybindings, layouts, window rulesxmonad.hsEdit → Super+Q, no rebuild
Panels, plugins, geometryXFCE via Home Manager XMLnixos-rebuild switch
Compositing (rounded corners)Picom (NixOS module)nixos-rebuild switch
Theme, GTK, terminal colorsHome Manager files + derived GTK themenixos-rebuild switch
Wallpaper galleryxfdesktop derivation overridenixos-rebuild switch
XMonad compiler + librariesNixOS services.xserver.windowManager.xmonadnixos-rebuild switch
Key decision: config = null on the NixOS xmonad module. XMonad runs as the vanilla launcher; it recompiles ~/.config/xmonad/xmonad.hs (a symlink to the user repo) with the Nix-supplied GHC + contrib libraries. Config edits never require a Nix rebuild or a display-manager restart.

3. The Nix Layer

Everything below lives in the tangled xfce-xmonad.nix module, edited only through its readme.org source block.

3.1 Services

services.xserver.desktopManager.xfce = {
  enable = true;
  noDesktop = false;    # xfdesktop, xfsettingsd, session management
  enableXfwm = false;   # XMonad is the only WM
};

services.xserver.windowManager.xmonad = {
  enable = true;
  enableContribAndExtras = true;  # adds xmonad-contrib/extras to GHC env
  config = null;                  # vanilla launcher; user config used
};

3.2 Panel geometry constants

Single xfceIslands record feeds both the XFCE panel XML and the Picom radius, keeping panel appearance coherent:

xfceIslands = rec {
  viewportWidth = 1920;
  radius = 12;      # corner radius (picom + GTK css)
  panelSize = 34;   # panel height, excluding the 2px GTK outline
  centerY = 26;     # vertical anchor
  left   = { lengthPercent = 1; centerX = 195; };
  center = { lengthPercent = 1; centerX = viewportWidth / 2; };
  right  = { lengthPercent = 1; centerX = viewportWidth - 200; };
  power  = { lengthPercent = 1; centerX = viewportWidth - 30; };
};

3.4 GTK theme

XFCE selects stock Adwaita-dark with Papirus-Dark icons through xsettings.xml. A short Home Manager-managed gtk-3.0/gtk.css supplies the palette and panel spacing. No custom theme derivation or global-menu module is built.

4. Panel Islands

Four position-locked panels float at y = 26 with enable-struts = false — they do not reserve screen space; XMonad’s layout gap (gaps [(U, 52)]) reserves it instead.

PanelPluginsAnchor
1 (left)Whisker menux = 195
2 (center)Clock %a %d %b | %I:%M %pviewport center
3 (right)Systray, PulseAudio, power-manager, notificationsx = viewport − 200
4 (power)Logout action buttonx = viewport − 30

GTK CSS removes native panel chrome so Picom supplies the rounded corners:

#XfcePanelWindow {
  border: 0;
  border-radius: 12px;
  box-shadow: none;
  margin: 0;
  padding: 0;
}
One geometry owner: XFCE positions panels from declarative XML. XMonad only reserves the top layout gap; it no longer contains duplicate panel-positioning logic.

5. Wallpapers

Desktop Settings only lists images inside <datadir>/share/backgrounds/xfce/ (non-recursive). An overlay rebuilds xfdesktop with symlinked images from nine collections (cosmic, pop, kde plasma, system76, gnome, budgie, elementary, pop-hp, adapta), flattened with prefixes to avoid filename collisions:

xfdesktop = prev.xfdesktop.overrideAttrs (old: {
  postInstall = (old.postInstall or "") + ''
    mkdir -p "$out/share/backgrounds/xfce"
    # find … -iname '*.jpg|*.jpeg|*.png' in each package,
    # ln -s into backgrounds/xfce/<prefix>-<path-with-dashes>
  '';
});

Result: 243 entries in the native gallery. Desktop icons are hidden via a declarative xfce4-desktop.xml (/desktop-icons/style = 0).

                      layoutHook xfceConfig
      , ... }

6.2 Window rules (manageHook)

Ordered — first match wins:

RuleEffect
_NET_WM_WINDOW_TYPE_DESKTOPlower + ignore (xfdesktop below everything)
title = Picture-in-Picturefloat + copy to all workspaces
manageSpawnapply placement recorded by spawnOn
class = Xfce4-panelpaint 2px accent border
Whisker menu (Wrapper-2.0 + type menu)float + focus
everything else, except firefox-beta / TelegramDesktop / Slackfloat by default

Default float is deliberate: this is a mouse-friendly stacking desktop. The three startup apps are exempted so they tile in the stacked layout on their assigned workspaces.

6.3 Startup apps on workspaces

startupAppOn :: WorkspaceId -> Query Bool -> String -> X ()
startupAppOn ws running cmd = withWindowSet $ \s -> do
  hits <- mapM (\w -> runQuery running w) (W.allWindows s)
  when (not (or hits)) $ spawnOn ws cmd

-- startupHook:
startupAppOn "1" (className =? "firefox-beta")  "firefox-beta"
startupAppOn "2" (className =? "TelegramDesktop") "Telegram"
startupAppOn "2" (className =? "Slack")           "slack"

Two cooperating halves:

  • Dedup — the Query Bool checks whether a window with that class already exists. Restarts with apps running spawn nothing.
  • Placement — spawnOn records the spawned PID plus a doShift hook; manageSpawn in the manageHook matches the new window’s _NET_WM_PID and applies the shift only to that window. Later windows launched manually are untouched.
Upstream has no spawnOnceOn; the two features live in different modules with different dedup mechanisms. The window-class check avoids both the process-name/class-name mismatch bug (Telegram’s binary is Telegram, its class is TelegramDesktop) and any shell-out to pgrep.

6.4 Session startup (startupHook)

startupHook = do
  startupHook xfceConfig
  paintWindowBorders          -- repaint borders of pre-existing windows
  paintPanelBorders
  spawn "snixembed"           -- SNI tray icons for xembed apps
  startupAppOn …              -- workspace apps, see above
  spawn "xfce4-power-manager" -- autostart doesn't fire in this hybrid session
  setWMName "LG3D"            -- Java AWT compatibility
  spawn "xfdesktop --disable-wm-check"  -- xfdesktop waits for an EWMH WM otherwise

nm-applet is not spawned here — programs.nm-applet.enable owns its autostart.

7. Fixed Accent

Window and panel borders use one explicit color:

accent :: String
accent = "#b75681"

No cache, theme parser, helper process, or dynamic refresh is involved. Super+Q only recompiles and restarts XMonad.

8. Daily Workflows

Change XMonad behavior

cd ~/projects/xmonad-config
$EDITOR xmonad.hs
# press Super+Q  (recompile; on failure the old WM keeps running)
git commit -am "…" && git push

Change panels, theme, packages, wallpapers

cd ~/projects/nixpkgs
$EDITOR readme.org            # edit the xfce-xmonad module block
emacs --batch readme.org --eval "(require 'org)" \
      --eval "(org-babel-tangle)"
nix build .#nixosConfigurations.nixos.config.system.build.toplevel  # validate
sudo nixos-rebuild switch --flake .#nixos
